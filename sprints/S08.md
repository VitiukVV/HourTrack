## Acceptance Criteria

- [ ] Settings page renders all sections (Profile, Interface, Data, Card Archive, Google Calendar, About) on a single scrollable page
- [ ] Language switcher in Settings persists to settings.language and updates i18next language live
- [ ] Theme switcher toggles light/dark/system; dark mode looks correct across all routes
- [ ] Default view switch updates `settings.defaultView` and is used as initial mode on next Home load
- [ ] Card archive section lists archived cards with `Restore` and `Delete permanently` (double-confirm) per row
- [ ] Hard-delete removes the card from Dexie; in S10 this will also propagate to Drive
- [ ] Backup and Calendar sections are visible but disabled with a "Sign in with Google" caption
- [ ] Mobile tab bar renders on small screens for Calendar / Reports / Settings
- [ ] Locale parity test passes (uk/en/es share identical keys)
- [ ] No inline duration/date string literals remain in the codebase (audit clean)
- [ ] App version visible in About section

## Notes

- This sprint closes Phase 1 acceptance: all 26 user requirements that DON'T require Google must be satisfied here
- Hard delete UX: two-step confirm + type-the-card-name (or double click within 3 seconds — whichever feels less intrusive). Document choice in code comment
- Stub sections for Backup / Calendar exist so users see the full Settings layout from day one; this avoids a visual "explosion" of new sections when Phase 2/3 lands
- Theme: when `theme='system'`, ThemeManager must subscribe to and unsubscribe from `matchMedia('(prefers-color-scheme: dark)').change` to avoid leaks
- Reaffirm: the active card store and card hard-delete must clear/update if the card is currently active (clear active state on hard delete)
