## Acceptance Criteria

- [ ] On first sync after auth, a "HourTrack" calendar is auto-created in the user's Google Calendar
- [ ] `settings.hourtrackCalendarId` persists across sessions
- [ ] Creating an entry creates a Google Calendar event with title `{cardName} | {H}H {M}M | {amount} EUR`
- [ ] Event description includes Card / Time / Rate / Earnings / Note lines per §9.2 spec
- [ ] Event colorId mapped from card.color via `GOOGLE_CALENDAR_COLOR_MAP`
- [ ] Updating an entry PATCHes the existing calendar event
- [ ] Deleting an entry deletes the corresponding Google Calendar event (cascade per req #9)
- [ ] Renaming or recoloring a card bulk-PATCHes all linked events
- [ ] `Re-sync all entries` button replays sync for every entry (mainly for repair after errors)
- [ ] `Disconnect Calendar` clears the calendar id locally without deleting existing events from Google
- [ ] Sync errors are visible per-entry in DayPage with Retry option
- [ ] Calendar operations use `calendar.app.created` scope only — no full `calendar` scope
- [ ] All strings localized in uk/en/es

## Notes

- The spec example `Raquel | 2H 45M | 36 EUR` rounds earnings to integer EUR in the **title only** (visual brevity). Description shows full 2-decimal value. Document this in `buildEvent.ts`
- All-day events use `start.date` and `end.date` (exclusive); end is `date + 1 day` per Calendar convention
- Bulk PATCH on card rename can be expensive for cards with many entries. Implement with concurrency-limited Promise pool (e.g., 3 in flight) and surface progress in toast for >10 events
- Disconnect does NOT delete existing events — this is intentional safety; user can manage Google-side cleanup themselves
- If `hourtrackCalendarId` was deleted by the user in Google Calendar, `insertEvent` returns 404 → handler detects this and forces ensureCalendar to recreate
- Per locked decision: cascade delete is one-way (app → Calendar). The reverse (Calendar deletion → app) is OUT OF SCOPE
