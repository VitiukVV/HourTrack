## Acceptance Criteria

- [ ] App is deployed to a Vercel default domain (`*.vercel.app`) and reachable over HTTPS
- [ ] Production build uses `VITE_GOOGLE_CLIENT_ID` from Vercel env vars
- [ ] PR previews automatically deploy via Vercel integration
- [ ] `docs/google-cloud-setup.md` contains step-by-step instructions complete enough for someone to fork and self-host
- [ ] OAuth consent screen requests only the 3 required scopes (`openid email profile`, `calendar.app.created`, `drive.appdata`)
- [ ] Authorized JavaScript origins include the Vercel prod URL + localhost:5173
- [ ] PWA install prompt appears on production URL
- [ ] Service worker registers and caches static assets
- [ ] Lighthouse production scores: Perf >= 90, A11y >= 95, Best Practices >= 95, PWA installable
- [ ] README.md has a working "5-minute self-host" quickstart
- [ ] All three locales render correctly on production
- [ ] Smoke test checklist passes end-to-end on production
- [ ] v1.0.0 tag created and pushed

## Notes

- Per locked decision: Vercel **default** domain only — do NOT configure a custom domain in this sprint
- The OAuth Consent Screen will start in **Testing** status; until verified, only listed test users can sign in. Document this in `google-cloud-setup.md` so the user knows to add themselves as a test user OR submit for verification
- For self-host: the OAuth client ID is per-deployment (each fork creates its own GCP project + client). The codebase ships no client ID; users must provide their own
- Vercel default domain may change if the project is renamed; document the implication for OAuth authorized origins
- Smoke test is a manual checklist; can be promoted to an automated Playwright run against production in a future sprint (out of v1 scope)
- Branding/icons are generated programmatically (req #19, low priority) — basic icons from S01 are sufficient for v1; refinement is OUT OF SCOPE for v1
