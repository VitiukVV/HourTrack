## Acceptance Criteria

- [ ] With a card active, clicking an empty day creates an entry with `durationMin = card.defaultDurationMin`
- [ ] Clicking the same day again with the same card active prompts to delete that entry
- [ ] Clicking a day with no active card opens NoActiveCardModal
- [ ] NoActiveCardModal lists all non-archived cards; selecting one creates the entry on that date
- [ ] NoActiveCardModal `+ Create new card and add` opens inline CardForm; saving creates both card and entry
- [ ] Delete entry shows confirm dialog before destructive action
- [ ] No drag-to-select is implemented; only single-click per day works
- [ ] Toast confirmations appear on create + delete success
- [ ] Newly created entries default `useCustomPayment=false` and copy `card.defaultNote` to `entry.note`
- [ ] Calendar markers (chips + note icon) refresh immediately after create/delete (TanStack Query invalidation)
- [ ] All new strings localized in uk/en/es

## Notes

- The single-click-per-day rule (req #23) is non-negotiable; do NOT add shift-click range, drag-to-select, or rubber-band selection in this sprint
- For the same-day-same-card uniqueness rule: this protects the active-card toggle UX. In the DayPage (S06) and via NoActiveCardModal, the user CAN add additional entries — those use explicit "Add entry" buttons, not the day-click pattern
- Newly created entries get `syncStatus: 'pending'` so when sync lands in S10, they automatically enqueue. For local-only Phase 1, treat `pending` as the steady state — no error
- `entry.note` initialization rule: if `card.defaultNote` is non-null/empty, copy it as the starting note; user can clear it later in DayPage. Document this in CardForm help text in S03 if needed
