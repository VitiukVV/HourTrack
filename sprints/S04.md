## Acceptance Criteria

- [ ] Home route renders MonthView by default (or WeekView if `settings.defaultView='week'`)
- [ ] Month grid has 7 columns, Mon→Sun, always starts on a Monday
- [ ] Prev/Next navigates by one month in month mode, one week in week mode
- [ ] "Today" button returns anchor to system date and triggers view to land on today
- [ ] Today's cell is visually distinct from other days
- [ ] Day cells show up to 3 entries; 4th and beyond collapse into `+N more` link to `/day/:date`
- [ ] If any entry on a day has a non-null note, a note icon shows in the cell corner
- [ ] Cell footer shows total duration (`{H}H {M}M`) and total earnings (EUR) for the day
- [ ] Week view shows 7 day columns Mon-Sun with all entries inline (no truncation)
- [ ] Title and weekday/month names are localized in uk/en/es
- [ ] Dates in week-view headers use `DD.MM` short form; full date format `DD.MM.YYYY` is used in day page
- [ ] No entry-creation or activation behavior here — that lands in S05 (this sprint is read-only display)

## Notes

- The calendar is **display-only** in this sprint; click handlers on day cells are stubbed (or no-op). S05 wires up active-card create/delete + DayPage navigation
- date-fns `weekStartsOn: 1` MUST be passed to every relevant call. To avoid drift, prefer the helpers from `@hourtrack/shared-utils/date-range` introduced in S02
- Multi-entry days: order chips by `createdAt` ascending so newer entries appear last (matches Google Calendar feel)
- The `+N more` link uses route `/day/:date` where `:date` is `YYYY-MM-DD`; this route's content is built in S06
- Earnings per day require **all entries for the card** in the period — `earningsForEntry` needs the full per-card entry list for fixed-rate proportional split. Fetch the wider scope (e.g., all entries for any card touching the period) inside `useEntriesInRange`
