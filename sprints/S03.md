## Acceptance Criteria

- [ ] User can create a card with name, color (from 12-color palette), default duration in minutes, rateType (hourly or fixed), and optional default note
- [ ] CardForm enforces: hourly cards require hourlyRate > 0; fixed cards require fixedTotal > 0
- [ ] User can edit any existing non-archived card via long-press → Edit
- [ ] User can archive a card (soft delete) — `isArchived=true`, `archivedAt` set
- [ ] Archived cards do not appear in CardsHeader
- [ ] User can restore an archived card from the Settings archive list (UI section landed; full Settings page wired in S08)
- [ ] Clicking a card chip toggles it as active; only one card can be active at a time
- [ ] Active card persists across in-app navigation (sessionStorage)
- [ ] Default duration is entered as Hours + Minutes (two integer inputs) and stored as `durationMin`
- [ ] Color picker shows exactly the 12 palette colors; no free hex input is allowed
- [ ] All UI strings are localized in uk/en/es
- [ ] cardSchema unit tests pass

## Notes

- "Long-press" on desktop = right-click context menu via `onContextMenu`; on touch = 500ms press detection. Use a single `useLongPress` hook to unify
- The active-card store lives in `sessionStorage` (not `localStorage`) — a new browser tab starts with no active card, matching the "fresh session" expectation
- Hard delete of an archived card is a destructive op behind double confirm; in S10 it will also need to be propagated to Drive `data.json`, but for now it just removes the Dexie row
- ColorPicker swatches must be a11y-friendly: each is a `<button>` with `aria-label="{colorName}"` and visible focus ring
- The `useActiveCard` store is referenced heavily by S05 (day-click behavior); keep its API small (`activeCardId`, `setActiveCard`, `clearActiveCard`) and stable
