## Acceptance Criteria

- [ ] Onboarding tour activates exactly once, on the user's first successful Google sign-in
- [ ] Tour has 3 steps: Create card → Activate card → Click calendar day
- [ ] User can skip the tour at any step; skip is final (never reappears)
- [ ] Completing all 3 steps sets `settings.onboardingSeen=true`
- [ ] Empty states across cards/entries/reports/archive provide helpful CTAs
- [ ] Reports route is code-split — initial bundle does not include Recharts
- [ ] Long entry lists (>20) on DayPage render virtualized
- [ ] Bundle visualizer report generated on `pnpm build`
- [ ] Playwright E2E suite covers the 4 golden paths and runs in CI
- [ ] axe-core a11y scan passes with zero critical violations on main routes
- [ ] Brand-new user can reach their first logged entry within 1 minute (manual UX check)
- [ ] All new strings localized in uk/en/es

## Notes

- Use `react-joyride` OR a custom positioned-portal implementation. If `react-joyride` adds significant bundle weight, prefer a small custom solution (~3 KB) since the tour is only 3 steps
- Onboarding step 2 requires a card to exist. If the user skipped step 1 without creating one, step 2 should auto-skip to step 3 OR show a different "Create one first" hint
- For Playwright mocking of GIS: intercept the token endpoint at the network layer and return a canned token. Stub Drive + Calendar API calls similarly. Document the mocking pattern in `e2e/README.md`
- Virtualization threshold: empirically 20 entries is the inflection point where rendering noticeably slows on mid-tier devices
- A11y critical violations block CI; serious + moderate are warnings only (to avoid blocking on minor color contrast edge cases)
