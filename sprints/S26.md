## Notes

- **Severity ≠ exposure here.** All 14 advisories are dev/build-only. A "critical" happy-dom RCE matters only when running untrusted code through the test runtime; the shipped PWA carries none of these. So the criticals are worth fixing because they're cheap (two upgrades), not because users are at risk. Don't let the scary count drive panic-bumping every major in one PR.
- **The happy-dom 15→20 jump is the real work.** Three majors of a DOM emulator under the entire vitest suite — expect a handful of test failures from changed DOM/ESM semantics. Isolate it: one commit, suite-green, before anything else. If it gets ugly, the fallback is migrating the test environment to `jsdom`, but that's a bigger decision — flag it, don't do it silently.
- **Prefer real upgrades over `pnpm.overrides`.** Overrides (js-yaml, @babel/core) are fine for transitive-only deps where the direct parent hasn't released, but they drift from what the parent tests against. Use them as the targeted tool they are; revisit when the parent catches up.
- **Bound your override ranges.** `@babel/core@<7.29.6 → >=7.29.6` looked right but resolved to Babel **8.0.1**, whose `^7` peer broke `workbox-build` (PWA service-worker generation) — the production build failed. Fixed by scoping to `>=7.29.6 <8`. Lesson: a security override should be the _narrowest_ range that clears the advisory, not an open `>=`. The unit suite + typecheck were green; only the **build** caught it — always run `pnpm build` (or e2e, which builds) after a build-chain override.
- **Sequence vs S25.** This sprint and S25 both touch `apps/web/package.json`. Land ONE first to avoid lockfile conflicts. Recommendation: do S26 Part A+B first (clean base), then S25 on top — S25's dnd-kit add + bundle measurement is more meaningful against an up-to-date vite/build chain. If S25 is urgent, at minimum don't run both in parallel branches.
- **`@types/node` should not chase latest.** Latest is 26 but it must match the Node major actually used in CI/Vercel. Bumping types ahead of the runtime invites false type errors. Pin it to the deployment Node line.
- **What this sprint does NOT do:** rewrite the test stack, migrate off pnpm/turbo, or adopt every major. It clears advisories, refreshes safe versions, defers risky majors with a paper trail, and installs a gate.
