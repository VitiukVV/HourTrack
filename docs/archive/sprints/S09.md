## Acceptance Criteria

- [ ] `/login` shows a single "Sign in with Google" button
- [ ] Successful Google sign-in stores access + refresh tokens in **IndexedDB** (not localStorage) and redirects to `/`
- [ ] Unauthenticated user visiting `/` is redirected to `/login`
- [ ] Access token auto-refreshes silently before expiry; user never sees a re-auth prompt unless refresh fails
- [ ] On refresh failure, silent re-auth (`prompt: 'none'`) is attempted before showing the login screen
- [ ] Profile menu in header shows Google avatar + email; clicking Logout calls revoke + clears Dexie auth row
- [ ] Settings → Profile shows the same data plus a Logout button
- [ ] Granted scopes are visible in Settings → About for transparency
- [ ] OAuth scopes requested: `openid email profile`, `calendar.app.created`, `drive.appdata` (the minimum per §9.1)
- [ ] PKCE flow used (no implicit flow, no client secret in browser)
- [ ] Logout removes tokens AND clears protected query cache
- [ ] All strings localized in uk/en/es

## Notes

- **Refresh-token-in-browser caveat:** Google's auth-code flow with PKCE for browser-only apps issues access tokens reliably; refresh tokens for browser clients require either (a) a tiny Vercel serverless function proxying the token exchange OR (b) accepting `prompt: 'none'` silent re-auth as the only renewal path. Per locked decision "Variant B — pure PWA + Google Drive (no backend)", default to **silent re-auth (prompt:'none')** as the primary renewal mechanism. If a refresh token can be obtained directly, store it; otherwise rely on the silent flow which works as long as the user is signed into Google in the browser. Document the choice in `lib/google/gis.ts` comments
- Refresh token (if obtained) MUST live in IndexedDB (Dexie), NEVER in localStorage — XSS containment
- The `tokenRefresh` worker runs in the main thread for now; if it impacts performance, move to a Web Worker in P4
- `prompt: 'none'` silent re-auth works only while the user is signed into Google in the same browser — that's the explicit trade-off in §9.1
- Do NOT request `https://www.googleapis.com/auth/drive` (full Drive) — req specifies `drive.appdata` ONLY. Same for `calendar.app.created` (not full `calendar`)
- The `firstLoginAt` marker is the cleanest signal for onboarding (S13) — set it once and never again
