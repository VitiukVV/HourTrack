## Acceptance Criteria

- [ ] `Create backup now` writes a new file to `backups/` in appDataFolder named `YYYY-MM-DDTHHmm.json`
- [ ] After 10 backups, the oldest one is deleted automatically (rotation)
- [ ] Auto-backup triggers automatically if `(now - lastBackupAt) >= autoBackupIntervalDays * 24h` (default 3 days)
- [ ] Auto-backup runs in background without blocking the UI
- [ ] User can toggle auto-backup OFF in Settings → Backup
- [ ] User can change `autoBackupIntervalDays` (1-30) in Settings
- [ ] Last backup timestamp shown in Settings: `{formatDate} HH:mm`
- [ ] Snapshot list shows all backups sorted newest first
- [ ] Restore requires two confirmation steps (modal + typed "RESTORE")
- [ ] Restore wipes local data, applies snapshot, pushes to Drive, then reloads
- [ ] Restore rejects snapshots with wrong schemaVersion
- [ ] Export-all CSV downloads all entries regardless of filter
- [ ] Backup errors show inline with Retry option
- [ ] All strings localized in uk/en/es

## Notes

- Backup filename pattern is `YYYY-MM-DDTHHmm.json` (e.g., `2026-05-14T1742.json`) — sortable lexicographically, which makes rotation trivial (sort + drop oldest)
- Auto-backup MUST be non-blocking: if it fails, surface a banner but never block user interaction
- The "Sign in with Google" disabled state from S08's BackupSectionStub is removed; section is fully active when authed
- Restore is destructive — emphasize this in the modal copy. Consider exporting a "pre-restore" backup automatically as a safety net (write to `backups/pre-restore-{ts}.json`)
- Validate the snapshot BEFORE wiping local data; an invalid snapshot must leave local data untouched
- Rotation policy keeps 10 most recent backups (per §4 storage model). Pre-restore safety backups count against this 10
- The hour-tick check inside `autoBackup` should use `setInterval(60 * 60 * 1000)` and clean up on unmount
