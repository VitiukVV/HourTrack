**Repo**: main | **Type**: FE | **Phase**: V2
**Size**: S | **Dependencies**: S13 (Reports surface)

> bar chart, pie chart, Recharts dependency) and replace the per-card
> aggregated table with a flat **entry-row** table (Date / Project /
> Hours / Sum). The metrics card (total hours + total earnings) and the
> filter bar stay as-is.

## Notes

- **Bundle baseline FIRST:** before any deletion, run `pnpm -F web build` on `main` and save the output (chunk names + sizes from the Vite build log, or `du -sh apps/web/dist/`). Re-run after the sprint and report the delta in the PR description. Without this anchor the "~140 kB gzipped" expectation is aspirational, not verified. If `rollup-plugin-visualizer` is wired in, snapshot `dist/stats.html` before/after as well.
- **Why drop `byDay` and `daysInRange`:** both fed exclusively the bar chart (`ReportData.byDay` → stacked bars; `daysInRange` → x-axis). With the chart gone they're dead weight. If a future sprint reintroduces a chart it can recompute from `byEntry`.
- **Why keep `byCard`:** `ReportsMetrics` and `ReportsTable` (old version) both consumed it. After this sprint, `ReportsTable` reads `byEntry`, but `ReportsMetrics` still sums via `byCard`/`totals`. Leave the computation in place — it's the source of truth for the totals card.
- **Tiebreak in row sort:** `entry.date` ASC is the primary key. Secondary tiebreak is by `entry.id` (stable, deterministic, no UI surprise). When **S16** introduces `entry.startMinutes`, switch the tiebreak to `startMinutes ASC` — the test for this lives in S16, NOT here.
- **Lazy route collapse:** ReportsRoute existed for one reason — Recharts mass. After this sprint Reports is small (few KB of UI + the report computation). Inlining the import simplifies `routes.tsx`, removes the `Suspense` fallback string, and shaves one render layer. If a future feature pulls in another heavy library on `/reports`, re-introduce the lazy boundary then.
- **CSV vs Excel terminology:** the user's wording was "Excel"; in the code only CSV exists. Both are removed under this sprint per V2_FEATURE_PLAN decision #3. No data-export path remains.
- **Bundle verification step (Task 5):** if `rollup-plugin-visualizer` isn't currently wired in (S13 task #10 promised it but check), use `pnpm -F web build` and `rg -uu recharts apps/web/dist` as a smoke verification instead. Visualizer setup is **out of scope** for this sprint.
- **Currency formatter:** the existing one used by `ReportsTable` and `ReportsMetrics` (via `@hourtrack/shared-utils`) handles the Sum column. Don't introduce a new formatter — match the existing style for consistency.
- **No schema or sync changes** — this sprint is purely UI + dependency hygiene. Dexie, Drive snapshot, Google Calendar sync untouched.
