## Acceptance Criteria

- [ ] `/day/:date` page renders for any valid `YYYY-MM-DD`; invalid params redirect home
- [ ] Page title shows localized weekday + `DD.MM.YYYY` date
- [ ] All entries for the date are listed in full (no truncation), one EntryRow each
- [ ] Hours and Minutes are TWO separate integer inputs; `durationMin = parseDuration(hours, minutes)` on save
- [ ] Custom payment toggle ON → user-entered amount is used as earnings; toggle OFF → earnings computed from card rate
- [ ] Per-entry note is independent from `card.defaultNote`; clearing it doesn't affect card default
- [ ] Deleting an entry from DayPage shows confirm dialog
- [ ] `+ Add entry to this day` opens picker with all non-archived cards + create-new option
- [ ] Adding an entry from DayPage focuses/scrolls to the new row
- [ ] Calendar note marker updates when a note is added or removed
- [ ] Autosave is debounced 500ms; no server-roundtrip required (still local-only)
- [ ] All strings localized in uk/en/es
- [ ] Earnings display uses 2-decimal EUR formatting (e.g., `36.00 EUR`)

## Notes

- Hours input bounded 0-23 keeps the UI clean; user can enter "23H 59M" max for a single entry. Multiple entries per day per card cover edge cases
- The custom payment value MAY exceed `hours × rate` per req #13 — there is no upper bound besides "positive number"
- Autosave fires on field blur OR after 500ms debounce; on validation error the field shows inline error and does NOT save
- `useEntriesByDate(date)` and `useEntriesByCardInMonth(cardId, monthAnchor)` should both be added to `useEntryMutations` queries layer — EntryEditor needs the broader set for fixed-rate split math
- Localized weekday name uses date-fns locale objects from S04's `getWeekdayName` helper
