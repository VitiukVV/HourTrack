# S19 -- Cards UX & Visual Unification + Header/Bottom-bar + PWA Icon

**Repo**: main | **Type**: FE | **Phase**: V2
**Size**: M-L | **Dependencies**: S18 (mobile baseline must be in place — touch targets, agenda, etc.)
**Plan Sources**: chat 16/05/2026 (UR-19-1..UR-19-10 below), plan file `abstract-cuddling-star.md`

> **Goal:** unify cards visually (background-color replaces the color-dot in
> every surface), make the hours/minutes input phone-friendly (numeric-only
> keyboard, select-all on focus, default 0), refresh the palette to 12
> contrasting hex values, redesign CardsHeader (icon-only "+" on the right
>
> - 3-dot menu for the active card), strip the avatar + sync dot out of
>   the page header, make the bottom nav always visible with a stronger
>   active state, and regenerate the PWA icon set in higher quality.

## User requirements (chat 16/05/2026)

- **UR-19-1** — Improve the hours/minutes input on the card: numeric-only keyboard, value clears on focus, default 0.
- **UR-19-2** — Provide 12 distinct colors (the current set has near-duplicates: green/emerald, stone/slate).
- **UR-19-3** — Improve the icon when installing on phone as an app (generate a higher-quality icon set).
- **UR-19-4** — On cards, drop the color dot → card background = card.color. Across the entire app.
- **UR-19-5** — Cards in the top header carousel should be the same size, roughly 6 characters wide.
- **UR-19-6** — The "Add card" button is the plus icon only, placed on the right side.
- **UR-19-7** — Instead of right-click on a card: when a card is selected, a 3-dot button appears next to the plus → edit/archive.
- **UR-19-8** — Across the app the words "hours" / "minutes" (and Ukrainian equivalents) are lowercase.
- **UR-19-9** — Hide the scrollbar when scrolling cards on mobile — on every page.
- **UR-19-10** — Remove the profile photo display and the status dot from the header (SyncIndicator).
- **UR-19-11** — The bottom nav bar must always be visible; improve the active-state styling.

## Notes

- **Legacy color migration is deferred, not skipped.** When the user opens an existing card in edit mode, ColorPicker shows their old hex as a "current" swatch. On next save, if they leave it, we keep it; if they pick a new-palette color, the card is normalized. Six months from now we can drop legacy compatibility entirely.
- **Background-color over dot is a SYSTEM change**, not a one-file refactor. Every surface that renders `card.color` as a dot must flip to bg-color. Grep `rounded-full` + `backgroundColor: card.color` to find them all. Don't ship Part B without sweeping all 6 sites.
- **`getReadableTextColor` is intentionally simple.** Y-luminance threshold > 0.5 picks dark text. A WCAG-grade contrast helper exists but is overkill for a 12-color palette where every choice was tested by hand. If a future palette change breaks contrast on one swatch, fix the swatch — not the helper.
- **DropdownMenu primitive is a NEW dependency.** Verified: `@radix-ui/react-dropdown-menu` is NOT in `apps/web/package.json` (deps: react-context-menu, react-select, react-dialog, react-switch, react-tabs, react-slot only). Task 17 explicitly installs it. Estimated bundle delta: ~5kb gz.
- **Bottom-nav scope is mobile/tablet ONLY** (per user clarification 2026-05-16). Top-nav stays on desktop unchanged. "Always visible" means: do not hide on scroll within mobile context — bottom-nav should remain sticky and reachable, not collapse when the user scrolls down. If any current code hides bottom-nav based on scroll position, remove that gating.
- **Sync indicator moves to Settings.** Its job (visible sync state, click-to-flush) is preserved — the user just stops seeing it in chrome. If feedback comes back that "I never know if it's syncing", we add a less-prominent bottom-nav indicator in S22.
- **PWA icon priority is `pwa-maskable-512x512.png`.** Android's adaptive icon crops it to a circle/squircle — without a 10% margin the design's edges get cut. This is the single most-noticed-on-install asset.
- **What this sprint does NOT do:**
  - Free color picker (any hex, not palette) — user explicitly chose palette in plan Q&A.
  - Avatar in any header — the user asked to remove, and there's no "but small avatar in Settings" carve-out.
  - SyncIndicator redesign — only relocate, don't restyle.
  - Top-nav redesign — desktop top-nav stays as-is.
