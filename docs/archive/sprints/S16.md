## Notes

- **Why split off from the original S16:** the monolithic S16 was 27 tasks crossing data + UI + sync layers. Slamming a destructive Dexie migration into the same PR as the CardForm/EntryEditor rewrite made the diff unreviewable AND made it impossible to test the schema in isolation before any UI consumed it. Splitting yields two PRs that each fit in one reviewer's head.
- **Why drop tombstones at v5:** tombstones reference entityIds that we just wiped. Leaving them produces "ghost deletes" on the next Drive snapshot push that would propagate empty deletes to any other device with the same Google account. Dropping them is the only correct option since the cards/entries they referenced are gone.
- **Why drop Calendar-related sync queue ops:** any `createCalendarEvent` / `updateCalendarEvent` / `deleteCalendarEvent` / `bulkUpdateCardEvents` op queued before the wipe references an entity that no longer exists; flushing them produces 404s. `pushDataJson` ops are preserved — they're Drive snapshot pushes and will simply push the (empty) post-wipe state, which is what we want.
- **No backward-compat.** Per V2_FEATURE_PLAN decision #2: destructive migration, v1 Drive snapshots rejected. Document in the PR description that this is a deliberate cutover and the moment v2.0 ships any real user data this approach is closed off forever.
- **TimeInput is unused this sprint** — that's intentional. Shipping the primitive separately lets S16b's PR focus on integration without also reviewing the component's keyboard/a11y behavior.
- **Why pin TZ in vitest setup:** S16b's `buildEvent` emits Google Calendar payloads with `start.dateTime` (no offset, no `Z`) PAIRED with `start.timeZone`. The timeZone field comes from `Intl.DateTimeFormat().resolvedOptions().timeZone`, which resolves against the host. CI runners (GitHub Actions, Vercel preview) are UTC. Dev machines are local. Without pinning, every test that asserts on `start.timeZone === 'Europe/Kyiv'` flakes. Pin once, document why, never debug it again.
- **Out of scope (S16b):** CardForm input, EntryEditor input, dayClick/DayPage prefill, buildEvent rewrite, calendarOps audit, EntryChip time prefix, ReportsTable sort tiebreak switch, resync hook.
