# S20 -- Reports Overhaul (Filters, Pickers, Table, GC Edit Regression)

**Repo**: main | **Type**: FE | **Phase**: V2
**Size**: L | **Dependencies**: S19 (palette helpers, `scrollbar-none` utility, layout decisions)
**Plan Sources**: chat 16/05/2026 (UR-20-1..UR-20-10), plan file `abstract-cuddling-star.md`

> **Goal:** rebuild the Reports filter bar to match the user's mental model
> (Month preset → month picker, Week preset → week picker; presets stay in
> one row across locales; reset is loud and resets to current month;
> there's a way to clear card selection separately). Fix two long-standing
> bugs: the duplicate date string next to the navigation arrow, and the
> Date column failing to stay sticky on vertical scroll. Move the card
> chip-row out of the sticky header so the user can scroll it away while
> reading the table. Add a regression test that proves editing an entry
> PATCHes the existing Google Calendar event rather than POSTing a new one.

## User requirements (chat 16/05/2026)

- **UR-20-1** — When the `Month` preset is clicked in Reports → the input shows the current month, not today's date.
- **UR-20-2** — Remove the pinned card row from Reports.
- **UR-20-3** — The Date column in the table does not stay put on vertical scroll — fix the bleed-through bug.
- **UR-20-4** — The duplicate date next to the right arrow of the date input — remove it.
- **UR-20-5** — With the `Month` preset selected, the input should be a month picker, not a day-of-month picker.
- **UR-20-6** — With the `Week` preset selected, the input should be a week picker.
- **UR-20-7** — The Reset button should be clearly visible (red) and reset filters to the current month.
- **UR-20-8** — Add a "Reset selected cards" button in Reports.
- **UR-20-9** — Reports preset buttons must stay on one row (bug — Reset jumps to a second row on language change).
- **UR-20-10** — Allow hiding the card chip row in Reports / move it higher so it scrolls away (user wants month + table visible, cards hidden once scrolled).
- **UR-20-11** — Verify that editing an entry in Google Calendar does NOT duplicate it but PATCHes the existing event — add a regression test.

## Notes

- **The MonthPicker is the heart of this sprint.** Native `<input type="date">` is great for a specific day but is a terrible UX when the user picked "Month" — they have to scroll a calendar to find a date in the month they already want. Replacing it with a real month grid is the single most-felt change.
- **WeekPicker complexity is medium.** ISO week numbering + cross-month weeks need care. `date-fns` has `getISOWeek` and `startOfISOWeek` — use those, not hand-rolled math.
- **Sticky Date bug fix is "z-index + bg-card", not architectural.** Don't refactor the whole table to make it work — the original sticky setup is correct, the cell needs z-20 and the wrapper needs to not be a positioning context that breaks sticky.
- **Reset button red is loud on purpose.** The user has felt the "hidden reset" frustration; making it red signals "I undo state". If a future review pushes back ("destructive should be reserved for delete"), counter that the reset action discards filter state and is therefore destructive in the right sense.
- **Reset-cards button only renders when needed.** Empty chip-selection (null = "all cards") doesn't need a reset affordance. Show the button only when the user has narrowed the selection.
- **Card chip-row out of sticky is the most subtle change.** Today the user can't scroll the chip-row out of view, which on mobile eats real estate. Putting it in the scrollable area means once they're reading data they have full vertical space.
- **GC edit regression test is preventative, not corrective.** The current code (`calendarOps.ts:patchEvent`) is correct — the patch flow already exists. The test exists so a future refactor doesn't silently break this contract.
- **`rangeForReports` already exists** (`apps/web/src/features/reports/useReportData.ts:31`). Do NOT invent a parallel `getPeriodBounds` helper. S21's `monthlyEarningsForPeriod` will import this and use the resulting `{start, end}` directly.
- **Popover primitive is a NEW dependency.** `@radix-ui/react-popover` is verified absent. Bundle delta: ~6kb gz for the popover + MonthPicker + WeekPicker combined. Acceptable budget vs UX win.
- **Rate-type Select refactor is grouped here (S20)** for cohesion with the other selects, even though it touches CardForm which S21 also edits. Sequence: S20 lands the Select refactor → S21 adds the `Monthly` option to that select. Both sprints touching CardForm is OK because they edit different sections.
- **What this sprint does NOT do:**
  - Date-range presets like "Last 7 days" or "This quarter" — out of scope; UR list doesn't mention them.
  - Quarter or year preset — not in UR list.
  - Saved filter views — not in UR list.
  - Replacing the native `<input type="date">` for the `day` and `custom` modes — that input is fine for a single-date pick; only `month` and `week` need the picker UX.
